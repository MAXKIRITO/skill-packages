# 前端去 AI 味與去平均值工作規範 (Frontend Anti-Slop)

在當代前端工程與 Vibe Coding 實踐中，AI 生成介面往往陷入兩大極端：要麼滑向「紫藍/紫粉漸層、等寬三欄、Emoji 藥丸」的典型 **AI Slop**；要麼在限制單一預設後，變成**每一次生成都長得完全一樣（千篇一律的陶土紅配米白、相同的直角按鈕）**，淪為另一種死板的公版收斂。

本 skill 是一套**通用、動態且以工程資產為導向的前端排版與設計去平均值規範**。核心在於：
1. **設計工程資產優先**：優先繼承專案已有之 `DESIGN.md`、Tokens 或主題設定。
2. **無文件時主動引導與動態流派配對**：主動提示使用者或依業務內容從「六大去平均值流派庫」動態選型，多樣化按鈕與版面語言，拒絕單一配色複讀。
3. **0-Card 開放式畫布**：以留白空間與 1px 細線替代白底圓角陰影卡片堆疊。
4. **兩階段強制合約閘門**：寫代碼前必須先輸出 6 行 `[設計合約鎖定]`。
5. **代碼只是假設，渲染才是事實**：透過瀏覽器反覆直接觀看，閉環驗收。

## ⚡ 核心原則（寫入任何前端代碼前必須無條件執行）

### 1. 第一優先：盤點專案既有設計工程資產 (Design Assets First)
在開始任何頁面生成或重構前，**必須先檢查專案中是否存在設計工程文件**：
- 檢查檔案：`DESIGN.md`、`design-tokens.json`、`tailwind.config.*`、`theme.ts`、Figma 變數或全域 CSS 變數。
- **規則**：若專案已有設計文件或使用者在 Prompt 中提供了具體色票、參考圖或品牌規範，**無條件以使用者的設計資產為第一準則（Ground Truth）**，嚴禁擅自替換為任何預設值！

### 2. 第二優先：無文件時主動對齊意圖，嚴禁單一死板複讀
若專案無設計文件，且使用者未指定風格：
- **主動提示與引導**：在回覆開頭告知使用者可提供設計文件，或從「六大去平均值流派庫」中挑選。
- **動態流派配對**：若使用者授權 AI 自主決定，AI **必須依據業務屬性動態匹配最適流派**（例如：資料工具匹配 Technical Utilitarian、智庫研報匹配 Editorial Print、創意平台匹配 Neo-Brutalist），**嚴禁每一次生成都輸出相同的顏色與按鈕！**

### 3. 結構鐵律：0-Card 開放式畫布（Open Canvas）
除非明確為數據密集型儀表板且需拖曳卡片，否則**嚴禁將頁面內容無端關進「白底圓角陰影卡片（Card-in-Card）」容器堆疊中**。
所有區塊必須直接坐在單一背景紙色上，僅以純粹的**留白空間（Spacing）與 1px 實線分割線（Hairline）**區隔層級與節奏。

## 1. 工作模式與兩階段強制閘門

| 模式 | 觸發條件 | 執行方式 |
| --- | --- | --- |
| **新建介面 (Greenfield)** | 從零建立任何新頁面、網站視圖或介面元件 | **強制執行兩階段閘門**：先檢查設計文件或提示使用者；輸出 6 行 `[設計合約鎖定]`，經確認後再輸出代碼 |
| **定向去 AI 味** | 針對特定頁面、元件或視圖進行局部去 AI 味重構；預設模式 | 檢核負向黑名單、破除卡片容器與漸層，**啟動預覽並直接觀看頁面渲染** |
| **系統性審查與重構** | 明確要求評估整站 UI 風格、建立專案級設計系統 | 執行特徵掃描，建立持久化 `DESIGN.md`，**多斷點直接觀看全頁**並產出審查報告 |
| **說明** | 詢問什麼是 AI 味、因果機制或去平均值原則 | 解釋統計收斂根因與參數落差；不修改專案程式碼，不啟動預覽服務 |

### 🚨 兩階段強制前置閘門 (The Greenfield Gate)
在新建介面模式下，**在輸出任何 `<html>`、`<template>` 或 `.tsx` 程式碼之前，回覆開頭必須先列出以下 6 行設計合約**（依據實際選用之流派或既有設計文件動態填寫）：

```plaintext
[設計合約鎖定]
- 設計資產來源：[專案既有 DESIGN.md / 使用者指定規格 / 動態匹配流派：例如 Technical Utilitarian]
- 色彩預算：底色 [代碼] / 主墨 [代碼] / 單一強調 [代碼]（全頁出現 ≤ 3 次，嚴禁多段漸層與光暈）
- 字體與級距：標題字體 (Display Size, weight) / 內文字體 (Body Size, weight) -> 跳躍比 ≥ 3.0x
- 版面骨架：12 欄不對稱佈局，主要資訊錨定，區塊以 1px hairline 分割，內文一律靠左
- 按鈕設計語言：[0px 直角實心 / 2px 線框反轉 / 編輯式底線文字 / 實體硬陰影 / 溫潤微弧度]
- 禁用確認：無白底圓角卡片堆疊、無 Emoji 標籤、無發光光環、無裝飾性偽狀態指示器、無樣板套話
```

## 2. 核心負向黑名單（全域生效）

無論使用者提示詞如何簡略，以下元素在任何介面生成結果中**絕對禁止出現**：

```xml
<anti_slop_core_blacklist>
1. 色彩與光影禁令：
   - 嚴禁紫藍漸層 (violet-to-indigo) 及任何紫粉漸層 (pink/fuchsia/purple/rose)。
   - 嚴禁頭像、圖標或容器外圍套上發光圓環 (glowing rings)。
   - 嚴禁背景散落任何高斯模糊彩色光球 (blur-2xl / blur-3xl blobs)。
   - 嚴禁點陣網格背景 (dot grid pattern) 與滿版毛玻璃 (backdrop-blur)。

2. 結構與排版禁令：
   - 嚴禁全頁卡片堆疊結構（白底大圓角卡片包多張白底小圓角卡片，外加微弱陰影）。
   - 嚴禁等寬三欄圖示卡片 (grid-cols-3)；嚴禁在項目旁放置淺色底圓圈線條圖示 (如 bg-blue-50/bg-yellow-50 圓圈)。
   - 嚴禁全頁 text-center 置中（大標題可置中，但副標、內文與說明一律靠左對齊）。
   - 嚴禁區塊垂直留白小於 120px（桌面端強制 ≥ 160px）。

3. 裝飾性假元素與微元件禁令：
   - 嚴禁無功能意義的懸浮偽狀態指示器（如帶綠點的 🟢「探索新機會中/Available/Live/Active」等無實際狀態綁定的偽 Badge）。
   - 嚴禁孤立的圓形圖示按鈕無端堆疊。
   - 嚴禁在標籤、按鈕或條目中塞入純裝飾性 Emoji 藥丸海（如 💻、🎨、⚡、🤖、☕、🚀、🔥 等）。

4. 字體與文案套路禁令：
   - 嚴禁預設 Inter / Roboto，且嚴禁次高機率滑落備案 Space Grotesk（除非搭配新粗獷高反差幾何網格）。
   - 嚴禁主標題以 700/800 粗體硬撐（字重必須維持 400–500，且字級跳躍比 ≥ 3.0 倍）。
   - 嚴禁任何無個性的 AI 樣板套話（如「熱衷於打造優雅、直覺且具備極佳體驗…」、「在技術與美感之間找到平衡」、「Unlock the power of...」、「簡單、快速、強大」等換成任何主題皆通用的空話）。第一句必須直接陳述具體功能、業務事實或實際數據。
</anti_slop_core_blacklist>
```

## 3. 標準流程

1. **盤點設計資產與意圖對齊**：
   - 優先搜尋專案目錄是否具備 `DESIGN.md`、Tokens 或 Tailwind 配置。
   - 若無，提示使用者提供品牌參考或從「六大流派庫」中選型；若交由 AI 決定，依據業務屬性動態匹配合適流派。
   - 在新建模式下，先輸出 6 行 `[設計合約鎖定]`，並同步在根目錄建立或更新 `DESIGN.md`。
2. **建構 0-Card 開放式骨架**：
   - 移除所有白底陰影卡片，改以背景紙色（`--paper`）鋪底。
   - 採用 12 欄不對稱佈局（如 60/40 或左 4 右 8 分割），各區塊以 `160px` 垂直留白與 `1px hairline` 分隔。
3. **注入排版張力與特色按鈕語言**：
   - 依據選定之流派注入字體組合與按鈕形式（直角實心 / 線框反轉 / 編輯底線 / 實體硬陰影 / 溫潤微弧）。
   - 主標題尺寸拉至內文 3.0 倍以上，字距收緊（`-0.02em`）。
   - 撰寫具體真實的微文案，刪除所有萬用形容詞。
4. **反覆直接觀看與視覺閉環 (Visual Critique Loop)**：
   - 啟動預覽（專案 dev server 或 `scripts/serve_preview.py`）。
   - **透過瀏覽器（或調度 `browser` subagent）直接觀看實際渲染**，捕捉桌面端與手機端截圖。
   - 提取實際計算樣式（paddingTop ≥ 160px、fontSize jump ≥ 3.0x、0-Card 無嵌套）。
   - 每次代碼微調後**重新直接觀看對比**，直到 20 項標誌降至 0–1 項。
5. **補齊功能與可訪問性（a11y）**：
   - 補齊鍵盤焦點框（`focus-visible:ring-2`）、ARIA 標籤與表單即時錯誤驗證。

## 4. 核心設計硬約束與證據規則

在執行任何 UI 生成或樣式改寫時，必須嚴格落實以下數值硬約束：

- **垂直留白硬標準**：主要區塊（Section）桌面端實際渲染之垂直內距必須達到 `160px`（`py-40` / `10rem`）以上；行動端不低於 `96px`（`py-24`）。嚴禁使用 64–96px 的擁擠模板留白。
- **字體與字級比**：
  - 全站僅限「一組標題字體＋一組內文字體」；禁止無端混用第三種字體。
  - 標題與內文實際計算字級比必須達到 `3.0 倍` 以上（如 Display 48–64px 對比 Body 16px）。
  - 主標題字重建議為 `400–500`（靠字級撐開氣場），或採極端對比 `200 vs 800`；嚴禁一律套用呆滯的 `font-weight: 700`。
- **色彩預算（Color Budget）**：
  - 最多定義 `3 個強調色`；每個強調色全頁最多出現 `3 次`（整頁合計不超過 9 個強調視覺點）。
  - 優先使用 `OKLCH` 色彩空間定義 CSS 變數，精準掌控感知明度與對比度。
  - 禁用紫藍與紫粉多段漸層；背景僅允許純色或角落單一極低透明度（≤ 8%）微弱徑向光。
- **幾何與邊界層次**：
  - 落實 0-Card 開放式畫布，優先採 0px 直角工藝風。
  - 依據流派嚴格約束組件圓角，嚴禁全頁泛濫套用 `16px`（`rounded-2xl`）。
- **版面與序列破除**：
  - 嚴禁全頁 `text-center` 置中；內文與副標題一律左對齊。
  - 禁用三欄等寬圖示卡片（`grid-cols-3`）；強制改用 `60/40 不對稱分割` 或 `開放式圖文條目`。
- **視覺觀看證據優先於代碼假設**：
  - 不得僅憑原始碼未出現黑名單字串就宣稱通過；必須透過瀏覽器直接觀看、截圖或 DOM 計算樣式測量值證實版面張力。
- **受保護頁面（需登入）安全與觀看規則**：
  - 遇到受 Auth Guard 保護的頁面時，優先透過前端 Mock Auth 獨立預覽路由進行直接觀看，使 UI 排版審查徹底解耦後端與認證。
  - 需要真實會話時，調度瀏覽器開啟登入頁，由使用者在可見視窗手動登入（人機協同）；嚴禁索取或硬編碼真實密碼，嚴禁嘗試自動破解 CAPTCHA 驗證碼。

## 6. 交付與完成條件

- **交付產物**：
  - 開頭包含已鎖定之 6 行 `[設計合約鎖定]`，清楚載明設計資產來源或動態選用之流派。
  - 遵循 0-Card 開放式畫布之完整前端原始碼（無任何白卡堆疊、無漸層發光、具備流派特色之按鈕與邊界語言）。
  - 本地持久化設計系統檔（`DESIGN.md`）。
