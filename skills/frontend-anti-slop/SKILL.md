# 前端去 AI 味與頂級視覺工藝工作規範 (Frontend Anti-Slop & Craft)

在當代前端工程與 Vibe Coding 實踐中，自動化介面生成往往陷入**兩大審美收斂陷阱**：
1. **第一種極端（典型 AI Slop）**：滑向「紫藍/紫粉漸層、等寬三欄卡片、Emoji 藥丸海、發光圓環」的典型科技新創模版套路。
2. **第二種極端（過度禁慾論文風 / Academic Monoculture）**：在要求去 AI 味後，模型矯枉過正地滑向「暖紙白背景（#F5F4F0）、陶土赭紅（#B84A2E）、Noto Serif 標題、1px 極細線、純文字無層次」的枯燥學術論文/電子報風格——全頁缺乏物料質感、無光學層次、無破格張力、無實體互動回饋，每一次生成都長得像單一預設公版。

本 skill 是一套**以真實人類頂級設計師實踐為基準、通用且具備物料觸感的工程級設計規範**。核心在於：
1. **設計工程資產優先 (Design Assets First)**：優先繼承專案既有之 `DESIGN.md`、Tokens 或主題設定。
2. **高槓桿設計意圖對齊卡**：無文件時，主動以「物料質感、空間張力、互動態度」向使用者錨定意圖，或自「八大先鋒流派庫」動態匹配，拒絕千篇一律複讀。
3. **6 項人類實體工藝方法 (Physical & Visual Craft)**：導入微噪點物料層、內切光學高光、複合混搭字體、破格重疊佈局、工藝符號標記與實體按壓物理阻尼。
4. **0-Card 開放式畫布**：以留白空間與結構性分割替代白底圓角陰影盒子堆疊。
5. **兩階段強制合約閘門**：寫代碼前必須先輸出 7 行 `[設計合約鎖定]`。
6. **代碼只是假設，渲染才是事實**：透過瀏覽器反覆直接觀看，閉環驗收。

## ⚡ 核心原則（寫入任何前端代碼前必須無條件執行）

### 1. 第一優先：盤點專案既有設計工程資產 (Design Assets First)
在開始任何頁面生成或重構前，**必須先檢查專案中是否存在設計工程文件**：
- 檢查檔案：`DESIGN.md`、`design-tokens.json`、`tailwind.config.*`、`theme.ts`、Figma 變數或全域 CSS 變數。
- **規則**：若專案已有設計文件或使用者在 Prompt 中提供了具體色票、參考圖或品牌規範，**無條件以使用者的設計資產為第一準則（Ground Truth）**，嚴禁擅自替換為任何預設值！

### 2. 第二優先：無文件時的高槓桿設計諮詢矩陣 (Design Consultation Matrix)
若專案無設計文件，且使用者需求較簡略時，**主動向使用者提供 3 個核心維度的設計選擇卡**（或在合約中依業務屬性進行明確的設計推導，嚴禁直接默認單一暖白陶土風）：
1. **物料質感 (Materiality)**：
   - `[實體硬體]` 工業消光面板、刻度滾輪、段碼 LED、機械微開關 (Teenage Engineering 風)
   - `[晶體黑曜石]` 深層黑曜石色階、1px 金屬內切高光、結晶微光 (Linear / Raycast 風)
   - `[有機紙質]` 暖調印刷紙、極微 SVG 膠卷噪點濾鏡、手工印章標記 (高階文化刊物風)
   - `[先鋒高彩]` 鮮豔高彩撞色、2.5px 粗黑輪廓、實體位移硬陰影 (Neo-Brutalist Pop 風)
   - `[極限東方]` 極度空靈「間」留白、超細字重、極簡朱印落款徽章 (MUJI / 原研哉風)
2. **空間張力與節奏 (Spatial Dynamics)**：
   - `[高密儀表]` 高密度資料矩陣、緊湊終端數據流、ASCII 邊框、極度緊湊高效
   - `[破格層疊]` 視窗邊緣外溢 (Bleed-out)、非對稱跨區塊重疊、黏性側欄滑動敘事 (Pinned Scrollytelling)
   - `[大器呼吸]` 極致留白、巨幅裝飾性排版浮水印、劇院式視窗焦點
3. **互動態度 (Interaction Attitude)**：
   - `[實體物理阻尼]` 按鈕具備真實下壓位移 (`active:translate-y-0.5`)、實體開關切換
   - `[精密磁吸光澤]` 邊框隨游標方向微流動、內切高光動態變化
   - `[生命狀態脈衝]` 即時遙測數據呼吸燈、滑動式分頁膠囊指示器

### 3. 結構鐵律：0-Card 開放式畫布（Open Canvas）
除非明確為數據密集型儀表板且需拖曳卡片，否則**嚴禁將頁面內容無端關進「白底圓角陰影卡片（Card-in-Card）」容器堆疊中**。
所有區塊必須直接坐在單一背景紙色上，僅以純粹的**留白空間（Spacing）與結構性分割線（Hairline）**區隔層級與節奏。

## 🛠️ 人類頂級設計師的 6 項實體工藝方法 (Craft Methodologies)

要徹底洗刷「枯燥生硬論文感」與「AI Slop 模版感」，介面產出必須選擇性注入以下實體工藝方法：

### 1. 微噪點物料層 (Organic Film Grain Overlay)
打破死板平滑的數位向量感，在背景底層注入 3%~5% 透明度的微噪點 SVG 紋理（`pointer-events-none`）：
```html
<!-- 注入底層有機噪點紋理 -->
<div class="fixed inset-0 pointer-events-none z-50 opacity-[0.035] mix-blend-overlay"
     style="background-image: url('data:image/svg+xml;utf8,<svg viewBox=\"0 0 200 200\" xmlns=\"http://www.w3.org/2000/svg\"><filter id=\"n\"><feTurbulence type=\"fractalNoise\" baseFrequency=\"0.8\" numOctaves=\"3\" stitchTiles=\"stitch\"/></filter><rect width=\"100%\" height=\"100%\" filter=\"url(%23n)\"/></svg>');">
</div>
```

### 2. 內切光學高光與階梯深度 (Specular Inset Highlights)
杜絕廉價發光與模糊陰影！高階暗色或深色介面採用頂部 1px 內切高光，模擬物理研磨玻璃或金屬切削邊緣：
```css
/* 頂部 1px 微光澤物理邊緣 */
box-shadow: inset 0 1px 0 0 rgba(255, 255, 255, 0.12), 0 20px 40px -15px rgba(0, 0, 0, 0.5);
```

### 3. 複合混搭排版 (Mixed Typographic Expression)
拒絕通篇單一字體的乾癟排版！在標題內刻意進行**字體風格混搭**或**巨幅背景圖形化**：
- **同句混搭**：在俐落的無襯線大標題中，刻意將核心動詞/形容詞設為 *Italic Serif*：
  `Crafting <em>deterministic</em> systems for high-load platforms.`
- **巨幅幾何背景浮水印 (Watermark Typography)**：將超大尺寸（96px~140px）、極低透明度（3%~6%）的幾何字形或序號（如 `01`、`SYS`、`ALPHA`）作為版面背景錨點。
- **邊緣垂直排版 (Vertical Writing Mode)**：在側邊留白處使用 `writing-mode: vertical-rl` 標示章節戳記或時間座標。

### 4. 破格與非對稱縱深 (Breaking the Grid & Pinned Scrollytelling)
拒絕永遠乖乖待在等寬 12 欄裡的無聊排版：
- **邊緣外溢 (Bleed-out)**：展示視窗或程式碼終端突破主容器邊界，延展至視窗邊緣。
- **跨區塊層疊重疊 (Overlapping Depth)**：關鍵數據晶片或操作列浮動覆蓋於兩大區塊的邊界線上（`margin-top: -32px; z-index: 10`），形成縱深。
- **黏性側欄滑動敘事 (Pinned Rail)**：左側（4 欄）固定核心指標與章節導覽，右側（8 欄）獨立平滑滾動展示長內容。

### 5. 工藝符號與工程刻度標記 (Bespoke Engineered Signage)
以充滿工程美感的細部標記替代呆板的 1px 全版線條：
- **座標與時間戳記**：`[ 25.0330° N // 121.5654° E — 10:42:01 UTC ]`
- **結構刻度線**：`+─── 02 // ARCHITECTURE ──────────────────────────────────+`
- **狀態脈衝微動態**：帶 `animate-ping` 的單一功能性小微燈（深綠、琥珀或電藍）。
- **微角度實體貼紙標籤**：`transform: rotate(-1.5deg)` 帶實黑描邊的小標籤。

### 6. 實體物理阻尼微互動 (Tactile Physics Micro-Interactions)
- **按鍵按壓深度**：點擊時產生微位移 (`active:translate-y-0.5 active:shadow-none`)。
- **滑動式分頁指示器 (Sliding Tab Indicator)**：切換分頁時，活動底色具有實體平滑過渡。

## 1. 工作模式與兩階段強制閘門

| 模式 | 觸發條件 | 執行方式 |
| --- | --- | --- |
| **新建介面 (Greenfield)** | 從零建立任何新頁面、網站視圖或介面元件 | **強制執行兩階段閘門**：先檢查設計文件或向使用者諮詢；輸出 7 行 `[設計合約鎖定]`，經確認後再輸出代碼 |
| **定向去 AI 味與注入工藝** | 針對特定頁面、元件或視圖進行去 AI 味與視覺工藝升級；預設模式 | 檢核負向黑名單、導入 6 大實體工藝方法，**啟動預覽並直接觀看頁面渲染** |

| **說明** | 詢問什麼是 AI 味、因果機制或去平均值原則 | 解釋統計收斂根因與參數落差；不修改專案程式碼，不啟動預覽服務 |

### 🚨 兩階段強制前置閘門 (The Greenfield Gate)
在新建介面模式下，**在輸出任何 `<html>`、`<template>` 或 `.tsx` 程式碼之前，回覆開頭必須先列出以下 7 行設計合約**：

```plaintext
[設計合約鎖定]
- 設計資產來源：[專案既有 DESIGN.md / 使用者指定規格 / 動態匹配流派：例如 Industrial Hardware]
- 色彩預算：底色 [代碼] / 主墨 [代碼] / 單一強調 [代碼]（全頁出現 ≤ 3 次，嚴禁多段紫藍/紫粉漸層）

- 物料與質感：[微噪點 SVG 紋理 / 頂部 1px 內切光學高光 / 消光塑料面板 / 實黑位移陰影 / 純平紙質]

- 禁用確認：無白底圓角卡片堆疊、無 Emoji 標籤、無發光光環、無偽狀態綠點、無空洞樣板句、無單一暖白枯燥論文複讀
```

## 2. 核心負向黑名單（全域生效）

無論使用者提示詞如何簡略，以下元素在任何介面生成結果中**絕對禁止出現**：

```xml
<anti_slop_core_blacklist>
1. 色彩與光影禁令：
   - 嚴禁紫藍漸層 (violet-to-indigo) 及任何紫粉漸層 (pink/fuchsia/purple/rose)。
   - 嚴禁千篇一律複讀單一暖白陶土公版（純暖白底 #F5F4F0 配陶土赭紅 #B84A2E，通篇無物料感無深度）。
   - 嚴禁頭像、圖標或容器外圍套上發光圓環 (glowing rings)。
   - 嚴禁背景散落任何高斯模糊彩色光球 (blur-2xl / blur-3xl blobs)。
   - 嚴禁無意義的等距點陣網格背景 (dot grid pattern) 與滿版毛玻璃 (backdrop-blur)。

2. 結構與排版禁令：
   - 嚴禁全頁卡片堆疊結構（白底大圓角卡片包多張白底小圓角卡片，外加微弱陰影）。
   - 嚴禁等寬三欄圖示卡片 (grid-cols-3)；嚴禁在項目旁放置淺色底圓圈線條圖示 (如 bg-blue-50/bg-yellow-50 圓圈)。
   - 嚴禁全頁 text-center 置中（大標題可置中，但副標、內文與說明一律靠左對齊）。
   - 嚴禁通篇死板遵循 12 欄且毫無層疊外溢的平面排版（缺乏深度與主次呼吸）。

3. 裝飾性假元素與微元件禁令：
   - 嚴禁無功能意義的懸浮偽狀態指示器（如帶綠點的 🟢「探索新機會中/Available/Live/Active」等無實際狀態綁定的偽 Badge）。
   - 嚴禁孤立的圓形圖示按鈕無端堆疊。
   - 嚴禁在標籤、按鈕或條目中塞入純裝飾性 Emoji 藥丸海（如 💻、🎨、⚡、🤖、☕、🚀、🔥 等）。

4. 字體與文案套路禁令：
   - 嚴禁預設 Inter / Roboto，且嚴禁次高機率滑落備案 Space Grotesk（除非搭配新粗獷高反差幾何網格）。
   - 嚴禁主標題以 700/800 粗體硬撐（字重必須維持 400–500，且字級跳躍比 ≥ 3.0 倍）。
   - 嚴禁任何無個性的 AI 樣板套話（如「熱衷於打造優雅、直覺且具備極佳體驗…」、「在技術與美感之間找到平衡」、「Unlock the power of...」、「簡單、快速、強大」等換成任何主題皆通用的空話）。第一句必須直接陳述具體功能、業務事實或實際數據。
</anti_slop_core_blacklist>
```

## 3. 標準流程

1. **盤點設計資產與意圖對齊**：
   - 優先搜尋專案目錄是否具備 `DESIGN.md`、Tokens 或 Tailwind 配置。
   - 若無，透過「高槓桿設計諮詢卡」提示使用者確認物料、張力與互動態度；或自「八大先鋒流派庫」中依業務動態選型。
   - 在新建模式下，先輸出 7 行 `[設計合約鎖定]`，並同步在根目錄建立或更新 `DESIGN.md`。
2. **建構 0-Card 開放式骨架與實體物料層**：
   - 移除所有白底陰影卡片，改以背景紙色（`--paper`）鋪底。
   - 依流派注入微噪點紋理（`SVG Noise Overlay`）或頂部內切光學高光（`inset 0 1px 0 rgba(...)`）。
   - 導入破格張力（如邊緣外溢、跨區塊重疊或黏性側欄導覽）。
3. **注入複合字體與特色按鈕語言**：
   - 依據選定之流派注入字體組合與按鈕形式（實體下壓阻尼 / 雙線反轉 / 實體硬陰影 / 雜誌底線 / 滑動分頁）。
   - 引入字體混搭（如標題內混入斜體襯線或等寬標記），主標題尺寸拉至內文 3.0 倍以上。
   - 撰寫具體真實的微文案，加入工程座標戳記或刻度符號，刪除所有萬用形容詞。
4. **反覆直接觀看與視覺閉環 (Visual Critique Loop)**：
   - 啟動預覽（專案 dev server 或 `scripts/serve_preview.py`）。
   - **透過瀏覽器（或調度 `browser` subagent）直接觀看實際渲染**，捕捉桌面端與手機端截圖。
   - 測量計算樣式（paddingTop ≥ 160px、fontSize jump ≥ 3.0x、0-Card 無嵌套）。
   - 每次微調後**重新直接觀看對比**，直到 20 項標誌降至 0–1 項。
5. **補齊功能與可訪問性（a11y）**：
   - 補齊鍵盤焦點框（`focus-visible:ring-2`）、ARIA 標籤與表單即時錯誤驗證。

## 4. 核心設計硬約束與證據規則

在執行任何 UI 生成或樣式改寫時，必須嚴格落實以下數值硬約束：

- **垂直留白硬標準**：主要區塊（Section）桌面端實際渲染之垂直內距必須達到 `160px`（`py-40` / `10rem`）以上；行動端不低於 `96px`（`py-24`）。嚴禁使用 64–96px 的擁擠模板留白。
- **字體與字級比**：
   - 全站僅限「一組標題字體＋一組內文字體」（支援標題行內斜體混搭與等寬輔助標記）。
   - 標題與內文實際計算字級比必須達到 `3.0 倍` 以上（如 Display 48–64px 對比 Body 16px）。
   - 主標題字重建議為 `400–500`（靠字級撐開氣場），或採極端對比 `200 vs 800`；嚴禁一律套用呆滯的 `font-weight: 700`。
- **色彩預算（Color Budget）**：
   - 最多定義 `3 個強調色`；每個強調色全頁最多出現 `3 次`（整頁合計不超過 9 個強調視覺點）。
   - 優先使用 `OKLCH` 色彩空間定義 CSS 變數，精準掌控感知明度與對比度。
   - 禁用紫藍與紫粉多段漸層；嚴禁千篇一律複讀單一暖白陶土色調。
- **幾何、物料與邊界層次**：
   - 落實 0-Card 開放式畫布，依據流派決定採用 0px 直角、2.5px 粗黑硬陰影、或 2px 微圓角。
   - 依據流派注入微噪點物料層或頂部內切光學高光，賦予介面真實物理深度。
- **版面與序列破除**：
   - 嚴禁全頁 `text-center` 置中；內文與副標題一律左對齊。
   - 禁用三欄等寬圖示卡片（`grid-cols-3`）；強制改用 `60/40 不對稱分割`、`開放式圖文條目` 或 `破格外溢展示`。
- **視覺觀看證據優先於代碼假設**：
   - 不得僅憑原始碼未出現黑名單字串就宣稱通過；必須透過瀏覽器直接觀看、截圖或 DOM 計算樣式測量值證實版面張力。
- **受保護頁面（需登入）安全與觀看規則**：
   - 遇到受 Auth Guard 保護的頁面時，優先透過前端 Mock Auth 獨立預覽路由進行直接觀看。
   - 需要真實會話時，調度瀏覽器開啟登入頁，由使用者手動登入（人機協同）；嚴禁索取或硬編碼真實密碼，嚴禁嘗試自動破解 CAPTCHA。
