# 前端去 AI 味與去平均值工作規範 (Frontend Anti-Slop)

在當代前端工程與 Vibe Coding 實踐中，AI 生成的介面往往具備語法正確的響應式程式碼，卻陷入「無品牌意圖的統計收斂」（AI Slop / AI Aesthetic Monoculture）。模型在未受嚴格約束下，必然輸出高度同質化的紫藍漸層、Inter 字體、700 粗體低跳躍比、64–96px 擁擠留白、均分三欄卡片與無差別 rounded-2xl 圓角。

本 skill 的核心目標在於：**透過設計系統硬約束改寫模型的機率搜尋空間，系統性偏離統計平均值，建立具備品牌識別、排版張力與完備互動細節的人類水準介面**。

## 1. 工作模式與授權範圍

| 模式 | 觸發條件 | 執行方式 |
| --- | --- | --- |
| 說明 | 詢問什麼是 AI 味、因果機制或去平均值原則 | 解釋統計收斂根因與參數落差；不修改專案程式碼，不新增設計設定 |
| 定向去 AI 味 | 針對特定頁面、元件、著陸頁或 Dashboard 進行局部去 AI 味重構；預設模式 | 檢核負向黑名單、導入排版張力與色彩預算，重構指定組件或版面 |
| 系統性審查與重構 | 明確要求評估整站 UI 風格、建立專案級設計系統或進行完整重構 | 先執行特徵掃描與評分，建立持久化 `DESIGN.md`，逐區重構並完成雙重審查閉環 |

**輸入**：目標網頁（HTML / JSX / TSX / Vue / CSS / Tailwind）、產品定位、真實文案、目標風格或參考範例。

**工作單位**：`介面區塊／元件 + 設計系統規範 (DESIGN.md) + 負向黑名單 + 審查截圖／代碼證據`。不憑空捏造未授權的品牌決策；涉及核心品牌調性或主色系更替時先向使用者確認。

## 3. 標準流程

1. **現狀盤點與特徵檢測**：掃描目標頁面或樣式，比對 16 項 AI Slop 標誌（Inter 字體、紫藍漸層、三欄卡片、全頁 text-center、均等 64–96px 內距、rounded-2xl 泛濫等），計算當前 AI 味程度（Heavy / Mild / Clean）。
2. **持久化設計系統約束**：在專案根目錄建立或讀取 `DESIGN.md`，並在專案提示詞（`CLAUDE.md` / Cursor Rules / System Prompt）中綁定該檔案，將視覺決策永久錨定，杜絕長對話中的上下文稀釋。
3. **注入負向黑名單**：明確宣告 `<anti_slop_constraints>`，除點名禁止第一層預設（Inter、violet-to-indigo、毛玻璃、Lucide 打勾圓圈），必須同步封鎖次高機率備案（如 Space Grotesk、Roboto），防止模型自動滑落至第二常見公版。
4. **維度隔離與極端排版張力**：將字體、色彩、留白與動效拆分設定。採用具備鮮明個性的字體組合（如雜誌編輯風、技術規格風），拉大字級跳躍比（≥ 3.0 倍）並控制標題字重（400–500），以尺寸撐開層級而非粗體硬撐。
5. **參考驅動與跨界混血**：以人類藝術總監角度拆解真實優秀設計（Mobbin / Awwwards）之比例結構，或刻意引入跨領域排版語言（如 1970 年代植物圖鑑、日本文具型錄、瑞士網格手冊），打破科技新創語料聚類。
6. **內容優先分段推進**：以真實標題長度與文案脈絡決定網格比例（如 60/40 不對稱），避免一次性單一大提示詞生成全站；逐區確認 Hero 節奏後再推展功能與定價區。
7. **雙重審查閉環與驗證**：執行截圖比對的視覺審查（抓出殘留公版痕跡）；緊接著補齊真實功能細節（表單必填標示、即時錯誤驗證、鍵盤 Focus ring、ARIA 標籤），交付重構前後對照與驗收結論。

## 4. 核心設計硬約束與證據規則

在執行任何 UI 生成或樣式改寫時，必須嚴格落實以下數值硬約束：

- **垂直留白硬標準**：主要區塊（Section）垂直內距必須設為 `160px`（`py-40` / `10rem`）以上；行動端不低於 `96px`（`py-24`）。嚴禁使用 64–96px 的擁擠模板留白。
- **字體與字級比**：
  - 全站僅限「一組標題字體＋一組內文字體」；禁止無端混用第三種字體。
  - 標題與內文字級跳躍比必須達到 `3.0 倍` 以上（如 Display 48–64px 對比 Body 16px）。
  - 主標題字重建議為 `400–500`（靠字級撐開氣場），或採極端對比 `200 vs 800`；嚴禁一律套用呆滯的 `font-weight: 700`。
- **色彩預算（Color Budget）**：
  - 最多定義 `3 個強調色`；每個強調色全頁最多出現 `3 次`（整頁合計不超過 9 個強調視覺點）。
  - 優先使用 `OKLCH` 色彩空間定義 CSS 變數，精準掌控感知明度與對比度。
  - 禁用紫藍多段漸層（`from-violet via-purple to-indigo`）與高飽和霓虹光暈；背景僅允許純色或角落單一極低透明度（≤ 8%）微弱徑向光。
- **幾何與圓角層次**：
  - 嚴禁按鈕、卡片與輸入框全數套用相同的 `16px`（`rounded-2xl`）。
  - 必須建立圓角階層（例如：按鈕 4px / 卡片 12px / 外層容器 0px 直角，或全頁銳利 0px 現代工藝風）。
- **版面與序列破除**：
  - 嚴禁全頁 `text-center` 置中；內文與副標題一律左對齊（或語系起始側對齊）。
  - 禁用三欄等寬圖示卡片（`grid-cols-3`）；強制改用 `60/40 不對稱分割`、`交錯圖文排版` 或 `單一主視覺 Tab 切換`。
- **文案與真實佔位**：
  - 嚴禁「Unlock the power of…」、「簡單、快速、強大」等萬用空洞標語。
  - 無真實用戶資料時，禁止放置五顆琥珀色星星、DiceBear 幾何頭像與假評價；改用文字縮寫圓標或直接省略。
- **功能性與無障礙（a11y）底線**：
  - 表單必須具備清楚必填標記、錯誤狀態文字提示、即時行內驗證。
  - 互動元素必須保留明顯的鍵盤導航焦點樣式（`focus-visible:ring-2`），並標註語意正確之 `aria-label` / `aria-describedby`。

## 5. 交付與完成條件

- **交付產物**：
  - 完整的去 AI 味原始碼（HTML / CSS / Component），且不含任何違背負向黑名單之樣式。
  - 專案持久化設計規範檔（`DESIGN.md`）及提示詞入口設定。
  - 重構前後對比清單，列出消除之 AI Slop 項目、採用的排版張力參數與 a11y 補齊細節。
- **停止條件**：
  - 目標頁面的 AI Slop 觸發項降至 0–1 項（達到 Clean 水準）。
  - 垂直留白、字級比、色彩預算與圓角層次均符合數值硬約束。
  - 若使用者對特定配色或字體有強烈個人偏好，以使用者明確決策為準，並在 `DESIGN.md` 中記錄授權例外，不反覆推翻已知偏好。
