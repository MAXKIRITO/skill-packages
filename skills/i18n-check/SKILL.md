# 多語系檢查

## 1. 工作模式

| 模式 | 觸發 | 執行方式 |
| --- | --- | --- |
| 說明 | 問方法、規則或概念 | 回答必要部分；無定位需求不掃 repo，不預設改檔或寫報告 |
| 定向處理 | 指定症狀、檔案、diff 或小範圍修改；預設模式 | 走下方流程，只展開本次相關檢查 |
| 範圍審查 | 明確要求檢查模組、介面集合或完整指定範圍 | 先列單位與排除項，再追覆蓋與缺口；完成只指已聲明範圍 |

輸入：畫面、key、locale、diff 或缺字症狀；來源語系與工具設定優先從專案確認。

檢查單位：使用處／namespace＋locale＋訊息類型。能由上下文確認的資訊不重問；只有會改變判斷或授權的關鍵缺口才詢問，不為填表要求額外資訊。

## 2. 按需讀取細節

詳細規範在 [PROCEDURE.md](references/PROCEDURE.md)。key／fallback 見第 1–2 節；語法與 UI 見第 3–4 節；腳本契約見第 5 節；驗證及案例見第 6–7 節。

先定位章節再讀必要片段，不預設整份載入，也不自動載入其他 skills。每個 skill 可獨立安裝，沒有 sibling skill 的隱含依賴。

需要範圍審查紀錄或正式報告時，再讀 [REPORTING.md](references/REPORTING.md)：它定義覆蓋狀態、問題欄位、反證、最後複核與報告模板。一般局部修正不需載入。

## 3. 標準流程

1. 設定：確認工具／版本、語系來源、key separator、namespace、fallback 與 lazy loading，不預設英文為來源語系。
2. 追蹤：對應靜態 key 與動態值集合到實際可用 locale；JSON 比較用附帶腳本，其他格式採專案原生工具。
3. 檢查：按本次類型核對插值、plural、rich text、formatter、硬編碼 UI 與語系切換反應性。
4. 驗證候選：先查 fallback、外部載入、工具語意及有效版本；無法窮舉的動態 key 標未覆蓋。不憑無靜態引用刪 key。
5. 驗收：做必要原生解析／格式化、build 或切語系 UI 驗證，區分已確認缺漏、人工翻譯判讀與工具盲點。

## 4. 證據與覆蓋規則

- 遵循專案規則與使用者授權。讀來源、提出方案、執行測試與修改環境是不同動作；載入 skill 不擴張授權，已有授權不重複確認。
- 證據標為 `source`、`test` 或 `runtime`，記錄當前路徑／符號、條件及結果；來源推論不得描述為已執行觀察，舊報告需對目前版本複查。
- 候選問題須有預期、具體差異、影響與來源。確認前查最可能的反證；反證成立即撤回，關鍵事實未定就明列缺什麼及如何驗證。
- 範圍審查用「檢查單位／已查位置／證據方式／結論／待驗證事項」簡表。未查項不能算通過，不適用需理由。局部修正保留必要上下文即可，不強制建立檔案。
- 修改或切版本後重新驗證依賴的證據。測試失敗須區分實作問題、既有失敗與環境限制；格式檢查成功不代表功能全數通過。

## 5. 交付與完成條件

交付範圍、已確認結果、最小修正（若有）、實際驗證與限制。多項問題按根因去重，再依已知影響排序；使用者要求報告時才保存到指定或約定位置。

不以 regex 取代 ICU parser，不自動大量翻譯。結構一致或 build 通過不能代替翻譯品質、動態引用及呈現驗收。

超出範圍、授權或可用環境時，停止依賴該條件的操作，繼續可完成的工作並給具體下一步。不以更多泛讀、無限重試或跳過失敗來宣稱完成。

## JSON 比較工具

僅在比較明確指定的 JSON 語系結構時使用 [compare_locales.py](scripts/compare_locales.py)，不需先讀完整腳本：

```sh
python3 /path/to/i18n-check/scripts/compare_locales.py --base /project/en.json --locale /project/zh.json
```

可重複 `--locale`，以 `--limit` 控制每類筆數。exit 0 為 leaf 結構一致、1 為差異、2 為輸入錯誤；完整輸出與盲點見 PROCEDURE 第 5 節。此工具不驗證插值、翻譯品質、程式引用或 UI。
