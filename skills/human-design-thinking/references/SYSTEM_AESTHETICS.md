# 系統化美學與視覺度量手冊 (Systematic Aesthetics & Metrics)

成熟的人類設計師配色與排版絕非「憑感覺挑幾個 Hex 色碼」或「隨機寫 `15px`、`18px` 間距」，而是建立在嚴謹的**比例紀律、感知均勻色彩空間、模組化字階與 8pt 空間網格**之上。

---

## 1. 60-30-10 色彩比例紀律與視覺焦點預算

源自空間建築與現代平面設計的 **60-30-10 法則**，是控制介面視覺重量與呼吸感的黃金律：

```
+-------------------------------------------------------------------------+
|                                                                         |
|                60% 主基調色 (Primary Neutral / Surface)                   |
|                大面積背景畫布、留白空間與襯底                              |
|                (低彩度中性色，負責承載內容、降噪防疲勞)                       |
|                                                                         |
|         +-----------------------------------------------------+         |
|         |                                                     |         |
|         |           30% 輔助結構色 (Secondary Structural)      |         |
|         |           側邊欄、卡片底色、表格容器、結構分割        |         |
|         |           (建立空間層次與資訊模組分區)               |         |
|         |                                                     |         |
|         |                        +------------------+         |         |
|         |                        | 10% 強調色       |         |         |
|         |                        | (Accent/Primary) |         |         |
|         |                        | 核心行動 CTA     |         |         |
|         |                        +------------------+         |         |
|         +-----------------------------------------------------+         |
+-------------------------------------------------------------------------+
```

### 比例預算職責與使用清單：
1. **60% 主基調色（Surface / Neutral Canvas）**：
   - 包含：全頁背景、主要負空間（Negative Space / Whitespace）、不可互動的襯底。
   - 特徵：極低彩度（Chroma < 0.02），淺色模式為暖米白/冷霧灰（OKLCH `L: 0.96~0.99`），深色模式為深炭黑曜石（OKLCH `L: 0.12~0.18`）。
2. **30% 輔助色（Secondary / Surface Containers）**：
   - 包含：側邊導覽欄（Sidebar）、卡片容器底色（Surface Container）、頁籤外框、表格交錯列。
   - 特徵：與 60% 主基調色維持細微但明確的明度差（Tonal Delta ΔL ≈ 0.04~0.08），用於組織群組。
3. **10% 強調色（Accent / Primary CTA）**：
   - 包含：頁面中當前最核心的 1~2 個主要行動按鈕（Primary Action）、啟用狀態指針（Active Indicator）、關鍵數據通知。
   - 特徵：高飽和度、高感知對比，全頁嚴格節制使用。**若全頁都是高彩度按鈕，就等於沒有重點**。

## 2. 感知均勻色彩空間：為什麼必須採用 OKLCH？

### 2.1 傳統 HSL / RGB 的致命盲點
傳統色彩空間（RGB、HSL）在數學座標上看似均勻，但人眼對不同波長光線的感知靈敏度極其不同（人眼對黃綠色最敏銳，對藍紫色最遲鈍）。
- 在 HSL 模式下，同樣設定 `Lightness: 50%`：
  - 純黃色（`hsl(60, 100%, 50%)`）的實際人眼感知亮度極高（眩目，且配白色文字完全看不見）。
  - 純藍色（`hsl(240, 100%, 50%)`）的人眼感知亮度極暗（沉重，且配黑色文字對比度嚴重不足）。
- 這導致過去在設計系統中無法透過數學公式直接衍生統一質感的色階，必須由人工手動校正幾十組 Hex 色碼。

### 2.2 OKLCH 的架構優勢
OKLCH 是依據現代心理物理學實驗（OKLab）構建的感知均勻色彩空間：
- **L (Perceptual Lightness, 0% ~ 100% 或 0.0 ~ 1.0)**：真實對應人眼感受到的亮度。
- **C (Chroma, 0.0 ~ 0.37+)**：色彩純度/飽和度。
- **H (Hue, 0 ~ 360 度)**：色相環角度。

**設計系統三大殺手級特性**：
1. **固定 L，任意切換色相 H**：當固定 `L = 0.65, C = 0.18` 時，切換 Hue 為 140（綠）、250（藍）、25（紅），三者的「視覺重量」與「相對於白底黑底的文字對比度」幾乎完全相等！
2. **預測可達性（Predictable Accessibility）**：只要確保前景色與背景色的感知亮度差（$\Delta L \ge 0.45$），即能近乎 100% 保證符合 WCAG AA 4.5:1 的對比度門檻。
3. **演算法生成 Tonal Palette（色階梯隊）**：
   - 透過鎖定 Hue 與 Chroma，依序將 Lightness 分級（從 950 的 `L: 0.15` 到 50 的 `L: 0.98`），即可完全自動化輸出無斷層的色階。

## 3. 語意化色彩角色架構（Semantic Color Roles）

參考 Material Design 3 (M3) 與現代 Design Token 實踐，色彩命名嚴禁綁死具體色相（例如避免命名為 `blue-btn`，而應命名為 `color-action-primary`）：

| 語意角色 (Role) | 設計職責 | 典型 OKLCH 數值範例 (淺色 / 深色) |
| :--- | :--- | :--- |
| **`surface`** | 頁面最底層畫布背景 | `oklch(0.98 0.005 240)` / `oklch(0.14 0.01 240)` |
| **`surface-container`** | 放置內容的卡片或浮層容器背景 | `oklch(0.95 0.008 240)` / `oklch(0.18 0.015 240)` |
| **`surface-container-high`** | 浮動彈窗（Dialog / Modal / Dropdown）背景 | `oklch(0.92 0.01 240)` / `oklch(0.22 0.02 240)` |
| **`on-surface`** | 位於 Surface 上的主要標題與內文（高對比） | `oklch(0.20 0.02 240)` / `oklch(0.95 0.005 240)` |
| **`on-surface-variant`** | 輔助說明文字、次要圖示、時間戳 | `oklch(0.45 0.02 240)` / `oklch(0.70 0.01 240)` |
| **`primary`** | 最核心互動按鈕、選中標記、品牌強焦點 | `oklch(0.55 0.22 255)` / `oklch(0.75 0.18 255)` |
| **`on-primary`** | 寫在 Primary 色塊內部的文字/圖示 | `oklch(0.99 0 0)` / `oklch(0.10 0.02 255)` |
| **`secondary`** | 次要操作、篩選膠囊（Pills）、標籤 | `oklch(0.60 0.08 240)` / `oklch(0.75 0.08 240)` |
| **`outline`** | 輸入框邊框、卡片邊界線（低調細線） | `oklch(0.80 0.01 240)` / `oklch(0.35 0.01 240)` |
| **`error` / `on-error`** | 警示中斷、刪除按鈕、驗證失敗訊息 | `oklch(0.58 0.22 28)` / `oklch(0.99 0 0)` |
| **`success`** | 操作完成、同步成功、正向狀態指示 | `oklch(0.62 0.19 145)` / `oklch(0.99 0 0)` |

### 色調階層替代重黑陰影（Tonal Elevation）：
在深色模式（Dark Mode）與現代介面中，**單靠模糊黑色陰影無法表達深度**（因為底色本身就是黑的）。
- 現代做法：越靠近使用者的圖層（例如從 Background → Card → Dialog），其 `surface` 的感知亮度 `L` 依次漸進提升（`L: 0.14` → `L: 0.18` → `L: 0.24`），配合 1px 內切高光微光澤，形成精緻的自然層深。

## 4. 字體排印與模組化比例（Modular Type Scale）

### 4.1 數學階梯比例
人類設計師不隨機挑選字級，而是選定一個模組化倍率（Scale Ratio $r$），以基準字級（Base Size，通常為 `16px`）呈幾何級數遞增：

$$Size_n = Base \times r^n$$

常見比例選型矩陣：
- **Minor Third (1.200)**：緊湊型儀表板、數據密集型 SaaS。
- **Major Third (1.250)**：標準 Web 應用、企業產品管理後台（**推薦預設**）。
- **Perfect Fourth (1.333)**：內容型網站、部落格、行銷落地頁（標題具備強烈視覺張力）。
- **Golden Ratio (1.618)**：極簡刊物、高階品牌形象官網。

以 **Major Third (1.250)** 為例之標準階梯表：

| 層級 Token | 比例公式 | 像素尺寸 (16px 基準) | 行高 (Line-height) | 適用場景 |
| :--- | :--- | :--- | :--- | :--- |
| `text-display` | $16 \times 1.25^4$ | `39.06px` (取整 `40px`) | `1.15` | Hero 巨幅標題 |
| `text-h1` | $16 \times 1.25^3$ | `31.25px` (取整 `32px`) | `1.20` | 頁面主要 H1 標題 |
| `text-h2` | $16 \times 1.25^2$ | `25.00px` (取整 `24px`) | `1.25` | 區塊 Section 標題 |
| `text-h3` | $16 \times 1.25^1$ | `20.00px` | `1.30` | 卡片標題、Modal 標題 |
| `text-body` | $16 \times 1.25^0$ | `16.00px` (基準) | `1.50` | 核心段落內文 |
| `text-caption` | $16 \times 1.25^{-1}$| `12.80px` (取整 `13px` 或 `12px`) | `1.40` | 表單提示、時間戳、徽章 |

### 4.2 排版易讀性三大鐵律：
1. **尺寸跳躍壓制字重依賴**：標題與內文的字級比應 $\ge 1.5x$（Hero 標題 $\ge 2.5x$）；透過尺寸跳躍拉開層次，而非把全部字都設為 `font-bold`。
2. **最佳閱讀行寬（Measure）**：
   - 英文內文長度控制在 `45 ~ 75` 個字元（約 `500px ~ 680px`）。
   - 中文內文長度控制在 `25 ~ 40` 個中文字。
   - **禁止**：讓內文橫跨滿版螢幕（例如 `1920px` 寬度一行到底），這會導致眼球換行追蹤極度疲勞。
3. **行高隨字級反比衰減**：內文字級小，需寬裕行高（`1.5 ~ 1.7`）；標題字級大，行高必須收緊（`1.15 ~ 1.25`），否則標題換行後看起來像兩個分離的段落。

## 5. 8pt / 4pt 空間網格系統（Spatial Grid）

### 5.1 空間尺度階梯
介面中所有外距（Margin）、內距（Padding）、容器尺寸與定位偏移，皆恪守以 `8px`（或微調半步 `4px`）為單位的乘數系統：

```
4px (0.5x)  -> 極微間距 (圖示與文字間隔、標籤內部垂直 Padding)
8px (1.0x)  -> 微間距 (緊湊清單項目間隔、輸入框垂直 Padding)
12px (1.5x) -> 中微間距 (輸入框水平內距、小卡片內距)
16px (2.0x) -> 標準基線 (通用元件內距、表單欄位間隔)
24px (3.0x) -> 次大間距 (卡片與卡片間隔、彈窗內部內距)
32px (4.0x) -> 大間距 (內容模組與標題間隔)
48px (6.0x) -> 宏觀間距 (區塊 Section 與 Section 之間隔)
64px (8.0x) -> 劇院宏觀 (大版面區塊分隔)
96px+ (12x+)-> 落地頁呼吸留白
```

### 5.2 微留白 vs. 宏留白（Micro vs. Macro Whitespace）
- **微留白（Micro Whitespace, 4px ~ 16px）**：負責「綁定元素」。當按鈕內部文字距離邊界只有 8px 時，文字與容器緊密形成一體。
- **宏留白（Macro Whitespace, 48px ~ 96px+）**：負責「劃分疆界」。宏留白是畫面的呼吸閥，讓大腦在不同功能區塊切換時獲得清空。
- **黃金鐵律**：**宏留白尺寸必須是微留白的 3 倍以上！** 若 Section 間隔也是 16px，整個介面就會像未解開的壓縮檔，產生嚴重的視覺窒息感。
