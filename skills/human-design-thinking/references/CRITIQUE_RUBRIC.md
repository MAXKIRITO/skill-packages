# 設計批判與審查標準清單 (Design Critique Rubric)

本審查清單包含 5 大核心維度、共 40 條可具體驗證的人類設計師審查指標。供 **Critic (審查質疑員)** 在頭腦互搏時發動對抗審查，亦作為自動化腳本驗證設計規格之權威依據。

---

## 維度一：問題定義與內容優先 (Problem & Content-First)

- [ ] **1.1 真實文案驗證**：是否杜絕了任何 `Lorem Ipsum` 或「測試標題一二三」等虛擬假字？
- [ ] **1.2 內容長度極限**：是否針對標題預先規劃了最長邊界長度（如 24 字元或多語系膨脹 +40%）與省略策略（`truncate` / `line-clamp`）？
- [ ] **1.3 核心任務聚焦**：單一畫面是否明確聚焦於 1~2 個核心行動（Core Action），而非讓多個功能平分秋色？
- [ ] **1.4 微文案明確性**：所有按鈕與操作文字是否採用「動詞 + 受詞」具體表述（如「建立新專案」而不是模糊的「確定」）？
- [ ] **1.5 失敗情境預想**：是否在定義流程時即預先考慮資料為空、斷網或操作失敗的應對機制？

## 維度二：視覺認知與格式塔心理學 (Gestalt & Visual Hierarchy)

- [ ] **2.1 接近性分群 (Proximity)**：表單標籤與輸入框的距離是否明確小於欄位之間的距離（比例通常為 1:3 或 1:4）？
- [ ] **2.2 共同區域簡約性 (Common Region)**：是否優先使用微明度差色塊（Surface Container）劃分模組，而不是在每個元素周圍加外框？
- [ ] **2.3 杜絕框中框反模式**：頁面是否避免了「卡片裡面包卡片、卡片再包帶邊框輸入框」的沉重線條堆疊？
- [ ] **2.4 主體與背景分離 (Figure/Ground)**：浮層、彈窗或下拉菜單是否具備足夠的明度差或背景遮罩，確保使用者焦點不分散？
- [ ] **2.5 相似性功能對齊 (Similarity)**：全站相同重要性級別的按鈕是否維持統一的圓角、內距與視覺重量？
- [ ] **2.6 連續性引導 (Continuity)**：橫向滑動或分步驟流程是否露出邊緣或指引線，直覺傳遞「可繼續探索」？
- [ ] **2.7 視覺層級限制**：單一畫面中的主視覺焦點（Visual Focal Point）是否嚴格限制在 3 個主要層級以內？
- [ ] **2.8 閱讀視線引導 (F/Z-Pattern)**：版面佈局是否符合自然閱讀習慣，核心資訊是否落在第一視線落點？

## 維度三：感知色彩系統與無障礙 (Perceptual Color & Accessibility)

- [ ] **3.1 60-30-10 預算紀律**：
  - 60% 主基調色（低彩度 Surface 畫布，維持大面積呼吸感）。
  - 30% 輔助色（側邊欄、卡片襯底、結構分隔）。
  - 10% 強調色（僅留給當前最重要之 Primary CTA 與核心狀態）。
- [ ] **3.2 OKLCH 感知均勻度**：色彩階梯是否基於 OKLCH 或感知均勻模型生成，避免黃色刺眼、藍色發黑的亮度失衡？
- [ ] **3.3 語意角色解耦 (M3 Roles)**：變數命名是否全面採用語意角色（如 `surface`, `primary`, `on-primary`, `outline`），絕無寫死色碼之色名變數（如 `blue-btn`）？
- [ ] **3.4 WCAG 2.2 AA 對比度**：所有內文與背景對比度是否達標（一般文字 $\ge 4.5:1$，大標題 $\ge 3:1$）？
- [ ] **3.5 杜絕過低對比次要字**：次要文字是否未濫用過淺灰階？（次要層級應透過適度縮小字級或位置留白達成，對比度依然必須合格）？
- [ ] **3.6 色調階層深度 (Tonal Elevation)**：前後圖層是否透過漸進提升的 Surface 明度表現深度，而非疊加厚重髒黑的高斯陰影？
- [ ] **3.7 非純色彩狀態指示**：錯誤、警告或成功狀態是否同時搭配了文字與圖示符標，避免色盲使用者無法辨識？
- [ ] **3.8 深淺色模式雙向適配**：語意 Token 是否在暗色模式下具備對應映射，且無任何硬編碼的 `#FFFFFF` 或 `#000000`？

## 維度四：字體排印與空間網格 (Typography & Spatial Grid)

- [ ] **4.1 模組化字階一致性 (Modular Scale)**：字級大小是否嚴格遵循模組化比率（如 1.25 Major Third 或 1.333 Perfect Fourth），無隨機自訂字級？
- [ ] **4.2 尺寸跳躍先於字重**：標題與內文尺寸比是否 $\ge 1.5x$（Hero 標題 $\ge 2.5x$），避免全頁靠 `font-bold` 製造廉價混亂？
- [ ] **4.3 最佳行寬控制 (Measure)**：內文欄寬是否嚴格控制在 45~75 字元（中文 25~40 字），無跨越全螢幕的寬面文字瀑布？
- [ ] **4.4 行高反比衰減**：標題行高是否收緊（`1.15 ~ 1.25`），內文行高是否保持寬裕（`1.5 ~ 1.7`）？
- [ ] **4.5 8pt/4pt 空間紀律**：所有內外距、尺寸與偏移是否為 8 的整數倍數（或 4px 半步）？
- [ ] **4.6 宏留白壓倒微留白 (Macro >> Micro)**：區塊與區塊間距（Section Spacing, 48~96px+）是否達到元件內部間距（4~16px）的 3 倍以上？
- [ ] **4.7 空間垂直節奏 (Vertical Rhythm)**：各區塊的垂直間距階梯是否穩定可預測，無隨機跳躍？

## 維度五：元件架構與 8 大互動狀態機 (Components & States)

- [ ] **5.1 W3C 三層 Token 抽象**：Primitive Tokens、Semantic Tokens 與 Component Tokens 是否清楚分層？元件是否未直接引用 Primitive？
- [ ] **5.2 元件解剖結構完整性**：複合元件是否定義了 Container、Leading Slot、Core Label、Supporting Text 與 Trailing Slot？
- [ ] **5.3 狀態一：Default (預設)**：可互動元件是否具備清晰的邊界符標（Signifier），無「扁平到看起來不像按鈕」的缺陷？
- [ ] **5.4 狀態二：Hover (懸停)**：懸停狀態是否有細微且優雅的亮度微調或位移，游標是否正確變更為 `pointer`？
- [ ] **5.5 狀態三：Focus-Visible (鍵盤聚焦)**：是否具備高對比雙層焦點環（Focus Ring），嚴禁 `outline: none` 未替代？
- [ ] **5.6 狀態四：Active / Pressed (按下)**：按下瞬間是否具備物理微縮放或下壓位移（阻尼感），傳達觸覺確認？
- [ ] **5.7 狀態五：Disabled (停用)**：停用元件是否具備降低透明度、游標鎖定，並有 Tooltip 解釋原因與解鎖方式？
- [ ] **5.8 狀態六：Loading (載入中)**：載入時是否保留原有尺寸避免版面跳動，且同時禁用點擊防止重複提交？
- [ ] **5.9 狀態七：Error / Validation (錯誤)**：輸入錯誤時是否具備紅色高對比外框、警示圖示與具體修復指引？
- [ ] **5.10 狀態八：Empty (空狀態)**：無資料時是否呈現溫暖的情境說明與明確引導建立的第一行動按鈕（Primary CTA）？
- [ ] **5.11 點擊熱區達標 (Touch Targets)**：所有可互動元素在行動端是否達到 $\ge 48\times 48\text{px}$（桌面端 $\ge 36\times 36\text{px}$）？
- [ ] **5.12 席克定律符合度 (Hick's Law)**：單一功能模組的主要操作選項是否在 3 個以內？
